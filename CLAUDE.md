# GramBas — заметки для Claude

Форк официального Telegram для Android (DrKLO/Telegram), собирается под именем
**GramBas**, пакет `com.rework.grambas`, репозиторий `0siriss/telegram_gx`.

## Границы проекта

Работа по этому аккаунту касается только форка GramBas. Есть старый побочный
проект (Telegram-X с патчем обхода DPI, собирался отдельными APK) — он
неактивен, к этому репозиторию не относится, продолжать его не нужно.

## Главное про архитектуру форка

`patches/fork-changes.patch` — единый источник истины для всех доработок форка
(42 файла, ~2957 добавленных строк). Рабочее дерево `master` — это свежий
upstream с уже наложенным этим патчем.

Отсюда главное правило: **правка исходников без перегенерации патча будет
потеряна** при следующем авто-апдейте, потому что он делает `git reset --hard`
на upstream и восстанавливает поверх только `.github/workflows`, `patches/` и
этот файл. Меняешь код форка — обновляй патч.

## Что уже работает (проверено на телефоне)

Это известный рабочий набор, спекулятивно рефакторить его не нужно.

Обход блокировок, нативный слой в `TMessagesProj/jni/tgnet/ConnectionSocket.cpp`
и `TgNetWrapper.cpp`:

- исправление расширения ECH, ID настраивается, по умолчанию `0xfe0d`;
- профили браузерного фингерпринта: Chrome, Firefox, Safari, Edge, Random, с ротацией;
- фрагментация TLS ClientHello;
- DPI shaping: размер записей, startup cover, джиттер таймингов. Массовые
  соединения (загрузки) от джиттера освобождены, иначе он режет скорость.

Настройки прокидываются из Java через `ConnectionsManager.setTls*` и
`setDpiShapingConfig`, UI живёт в `ProxySettingsActivity`.

Свой экран настроек `GramBasSettingsActivity`, флаги — статические методы в
`MessagesController`:

- anti-recall, показ удалённых отправителем сообщений. Тонстоуны хранятся в
  таблице `recalled_messages(uid, mid, recalled_date)`, есть миграция в
  `DatabaseMigrationHelper`;
- сохранение самоуничтожающихся медиа;
- разрешение скриншотов и подавление уведомления о скриншоте в секретных чатах;
- фоновая предзагрузка входящих голосовых;
- скрытие спонсорских сообщений и рекламы в видео;
- keep-alive: `ConnectionKeepAliveService` держит foreground-сервис, чтобы не
  засыпало MTProto-соединение. Нужен потому, что настоящий FCM push не работает
  с самоподписанным APK и собственным проектом Firebase. Есть дебаунс, он
  предотвращает падение при старте foreground-сервиса.

Встроенный апдейтер: `GithubUpdaterController` плюс `UpdateAppAlertDialog` и
`UpdateLayout`. Опрашивает последний релиз `0siriss/telegram_gx` и предлагает
поставить `app.apk`.

Версия форка показывается в настройках рядом с версией Telegram, берётся из
`BuildConfig.FORK_VERSION_TAG`. В CI он приходит из `FORK_VERSION_TAG:
${{ github.ref_name }}`, локально откатывается на `git describe --tags`.

## Тон пользовательских текстов

Любой текст, который читает конечный пользователь — тело GitHub Release, окно
обновления в приложении, changelog — пишется простым языком без технического
жаргона. Никаких TLS, ECH, фрагментации, shaping. Описываем выгоду, а не
реализацию: «улучшенная маскировка трафика», «соединение труднее распознать и
заблокировать». Это прямое требование пользователя, применять по умолчанию.

## Механизм авто-апдейта и релиза

`.github/workflows/auto-update.yml`, раз в неделю или вручную. Сравнивает
`APP_VERSION_NAME` в корневом `gradle.properties` с upstream. При различии:
`git reset --hard upstream/master`, восстановление `.github/workflows`,
`patches/` и `CLAUDE.md` из предыдущего форк-коммита, наложение патча через
`git apply --3way`, коммит, тег, **force-push в master**, запуск `build.yml`,
уведомление в Telegram.

Force-push здесь сделан намеренно, это не поломка. Реальная история master —
много мелких инкрементальных коммитов на старом снапшоте upstream, а
авто-апдейт пересобирает состояние из свежего upstream плюс один большой патч.
Обычный merge через PR между этими двумя линиями невозможен, GitHub показывает
`mergeable_state: dirty` с тысячами конфликтов в сгенерированных upstream файлах
вроде TL-схем, а не в коде форка. На практике проверено: переналоженный патч
получился байт-в-байт тем же, что уже был в истории master, то есть код и фичи
не теряются, сворачивается только промежуточный лог коммитов. Старые ветки с
фичами и фиксами остаются на remote. Для будущих синхронизаций с upstream
использовать тот же подход, если пользователь не скажет иначе.

`build.yml` срабатывает на push тега `v*`, собирает release APK и публикует
GitHub Release. Если релиз для тега уже существует, APK просто перезаливается, а
вручную выставленные заметки не затираются. Дефолтный текст заметок захардкожен в
самом workflow, держать его простым по правилу выше. В checkout обязателен
`submodules: recursive`, иначе сборка падает без ffmpeg, libvpx и opus.

Новый тег считается из последнего существующего: первое число — major, последнее —
minor, minor увеличивается на единицу. Сортировка `--sort=-v:refname`, так что
после ручного трёхкомпонентного тега вида `v2.2.1` очередной тег нужно поставить
руками.

## Состояние на 2026-09-12

Upstream 12.10.1, сборка 7038. Тег `v2.3` создан и указывает на текущий head
master, сборка релиза для него шла на момент записи. Последний опубликованный
релиз до этого — `v2.2.1`, помечен как prerelease.

Апстримной фичи «web proxy» в опенсорсе пока нет, она только в бете Telegram
для Android (12.10.2, сборки 7060+, «WEB proxy (wip)»). Забирать нечего, пока
DrKLO не опубликует стабильную версию с ней.
